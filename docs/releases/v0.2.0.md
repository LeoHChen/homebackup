Making the server easier to run and manage, and the Mac app easier to understand. Your home server now has a web dashboard, any paired device can hand out pairing codes, and the Mac app explains what it needs instead of failing quietly.

## Server (`homebackupd`)
- **Web dashboard** at `https://<server>:8420/`: free space on the backup drive, each backup's size and state, a getting-started checklist, Files and Photos browsing with thumbnails, download, previous versions and trash restore, uploads and new folders in My Files, paired devices with revoke, recent Activity, and Settings. A browser pairs with a code like any other device.
- **Pairing codes from any paired device:** `POST /api/v1/pair/codes`. Only the first device ever needs `homebackupd pair` on the server; after that, use the Mac app's **Pair another device…** or the dashboard's **Devices → Add a device**.
- **Richer status:** `GET /api/v1/status` reports disk space, per-source file counts and sizes, trash size, retention, and the paired-device count.
- **Recent log in memory:** `GET /api/v1/log` returns the last lines, including TLS handshake errors from the HTTP server.
- The startup log prints the dashboard URL, and `homebackupd pair` mentions it.
- `make sign` signs the macOS binary with a Developer ID so macOS keeps the removable-volume permission across updates.

## Mac app
- **Fixes pairing on macOS 15 and later.** The app and its Finder extension now share a Team-ID-prefixed app group, which macOS accepts without a provisioning-profile entry and which also works as the keychain access group for the device token. Before, the token could only be saved in the login keychain, where the Finder extension could not read it.
- Explains when macOS has the File Provider extension turned off ("Finder can't show your files yet") and opens System Settings to the right place.
- Plain-language errors instead of raw error text: unreachable server, revoked device (with **Pair again**), key mismatch.
- Shows free space on the backup drive and each backup's state; **Pair another device…** shows a code for an iPhone, another Mac, or a browser; **Open dashboard**.
- The pairing window walks through three steps, explains when no server is found, and says what to expect after pairing.

## Shared Swift library
- `UserMessage.describe` turns errors into sentences for people; new `status()`, `newPairCode()`, `devices()`, and `revokeDevice()` calls.

## Upgrading
- **Server:** put the new binary in place as a new file (`mv` the old one away, then copy the new one in; never `cp` over the running file), then restart. See [Update](https://github.com/LeoHChen/homebackup#update-roll-back-uninstall) in the README. On macOS with the root on an external drive, macOS asks once on the server's screen whether `homebackupd` may access the volume; click **Allow**. Sign the binary with `make sign` to be asked only once across updates.
- **Mac app:** replace `/Applications/HomeBackup.app` and open it, then pair again (menu → **Connect to your home server…**). If the menu says Finder can't show your files yet, turn on HomeBackup under File Providers in System Settings.
- **iPhone app:** build it with Xcode as before; it keeps its pairing.

## Known limitations
- Early release: keep your cloud accounts while you try it.
- The dashboard downloads files through the browser's memory, so very large videos are better fetched from Finder.
- No off-site copy and no remote access outside the home network yet.
